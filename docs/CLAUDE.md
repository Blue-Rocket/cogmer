## Writing documentation

Follow `docs/writing.md` for every document in this repository. It holds the rules, the
words and marks to avoid, and a template for each kind of item: a decision, an `open.md`
item, a behaviour-registry entry, a specification requirement and a commit message.

Before committing a change to a document, run the `writing-review` skill on it. It
reports what the tests cannot decide, and changes nothing.

# D-308 — The static page is sent a page of a room's turns and asks for the earlier ones

**Date:** 2026-11-26 · **Status:** active · **Areas:** view, transport

**Decision.** The static page that reads a cloud session's room (D-302, a cloud session's room is read on a static page, the daemon's own view served from GitHub Pages) is sent the newest turns of the room and not all of them: up to 20 turns, stopping once their text and its Markdown come to 300 KB, and never fewer than 10. A button above the turns asks for the turns before the oldest the page holds, in pages of the same size. Each turn carries the place it sorts in, the page keeps every turn it has fetched in that order, a newer page takes the place of the turns from its first on, and an earlier page goes in front. The daemon sends with the newest page how many turns the room holds, how many of them no session holds, and whether turns come before it, since the page cannot count what it was not sent. It sends too the turns that appear nowhere (D-234, a machine not certified under the current shared key is suspended until it is certified again) and why a turn does not count (D-220, a removal names the last event of a machine that counts, room by room; D-236, a revocation names the last turn of each of the revoked user's machines that counts), so that a turn the page holds follows a suspension, a revocation or a removal. A room of 300 turns came to 316 KB on 2026-11-26, a room of 3,000 turns would come to about 3 MB, and a phone draws every turn it is given.

**Rejected.**
- *The turns after the last one the page holds.* A turn the page holds changes without a new event: whether a session holds it, who a colleague is called, whether its machine was removed and the pictures that arrive, and it can leave the room's view. A page that took only new turns would show those as they were.
- *Hashes of each turn kept by the daemon for the snapshots it has sent.* The daemon would hold the snapshots to compare with, for a saving that a page gets with nothing held.
- *Pages of a number of turns alone.* An assistant's turn runs to several kilobytes, so 20 of them can come to more than the page should carry, which is what the byte limit is for.

**Limits.** A turn on a page the reader asked for keeps what it was sent until the page is opened again, so the tag that says no session holds it, and a label, are not changed there. A turn that arrives late and sorts among turns outside the newest page does not appear until the page is opened again, which departs from D-204 (the view keeps the reader's place, says what the model holds, and exports the room), where a late turn is put where it sorts, for those turns. The daemon still reads and sorts a room's events to cut a page, which cost 36 ms for 300 turns in a run on 2026-11-26, since nothing indexes the order a page is cut by. The room the loopback page shows is sent whole.

**Revisit when** reading a room's events to cut a page costs the daemon more than sending them costs the page, or a reader needs to find a turn in a long room.

# D-301 — A cloud session's daemon serves its room to a static page over a second overlay port, with a token made from the cloud key

**Date:** 2026-11-25 · **Status:** active · **Areas:** transport, view, trust

**Decision.** A daemon whose environment is a cloud container serves port 4784 of the overlay, beside the peer port 4783, which a page in the user's browser reads the room through. The port speaks lines and not HTTP: a connection opens with the token on a line, each request after it is a path on a line and always a read, and each answer is a line of the status, the media type and the length of the body, followed by the body. It serves only the room as the view draws it, the list of rooms, the image of a turn and the export. The token is the HMAC-SHA256 under the cloud key's seed of a fixed label, so the same cloud key makes the same token after every wake and in every task and nothing is stored, and a daemon that holds no cloud key serves nothing. The overlay admits any dialer (D-157, the overlay listener admits any dialer) and encrypts what it carries, which is why the port needs a token and not TLS, since a browser has no TLS client to run over the connection that tailcat's browser build returns. `/cogmer:room-join`, `/cogmer:room-create` and `/cogmer:room-status` print a link that carries the daemon's address, the token and the room in its fragment, which a browser does not send to the host of the page, and the daemon makes the link for the command over loopback. The page is the daemon's own view, `cmd/cogmer/ui.html`, with `web/view/viewer.js` added at the place the view marks, built with tailcat's browser build by `scripts/build-view.sh` and published by `scripts/publish-view.sh` to the `pages` branch of `Blue-Rocket/cogmer`, which GitHub Pages serves at `https://blue-rocket.github.io/cogmer/view/`. The page polls the room every three seconds in place of the view's streams, and says the session is asleep when a dial takes more than 15 seconds. A browser reached a cloud task's daemon on the peer port through the relay in about 3 seconds once the module was ready (`ad8b5ed`).

**Rejected.**
- *Serving the view's routes on the TLS peer port.* The page would carry a TLS implementation to run over the tailcat connection, which is more code in the browser than the token is.
- *HTTP on the port.* The page would carry an HTTP/1.1 client that decodes chunked replies and keeps a connection open, which only a JavaScript engine could test, and a machine that builds cogmer is not required to have one. Lines leave the page a line and a length to read, and the daemon's side is tested in Go.
- *A token made fresh at each start.* A sleeping task wakes often, and each wake would break the link a user holds.
- *A token stored for each task.* It needs a file and a rule for when it changes, and the derived token needs neither.
- *A gateway or a hosted machine that serves the page at an address on the internet.* It puts a component somebody else operates between the user and the room, and its host has to be allowed in the cloud environment.
- *Serving the port in every daemon.* A computer's daemon has its page on loopback, and the port would be open for every user.
- *A mod that draws the room.* A cloud session draws nothing, and the mobile app shows a mod only in the terminal on the user's own machine (Anthropic's page on mods, read on 2026-11-18, `d5140d4`).
- *A hook's `systemMessage` or a file in the session's outputs folder.* Neither Desktop nor the mobile app showed either, at a prompt sent from the phone as well (`a6cffcc`).

**Limits.** Anyone who holds the link can read the room while the daemon is awake, the link is in the conversation of the session, and the token is the same in every link of one cloud key until that key changes. The host of the page serves the script that reads the token, so that host has to be trusted. A first visit downloads a 27 MB module, 6.6 MB if the host compresses it, which no run has measured from GitHub Pages or over a phone's connection. A sleeping task's daemon is unreachable and only a prompt in the task wakes it. Traffic goes through the relay and never directly, and tailcat's README calls its browser demo experimental.

**Revisit when** a user on a computer should read their room from a phone, or tailcat's browser build gets direct connections, or Anthropic draws mods for a cloud session.

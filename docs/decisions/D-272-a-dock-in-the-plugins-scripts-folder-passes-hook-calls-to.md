# D-272 — A dock in the plugin's scripts folder passes hook calls to the installed program

**Date:** 2026-10-28 · **Status:** not built · **Areas:** release, daemon

**Decision.** The plugin carries one dock, `cogmer-dock`, in its `scripts/` folder, and a hook line names it by `${CLAUDE_PLUGIN_ROOT}/scripts/cogmer-dock`. `cogmer-dock [--host <host>] <arguments>` runs the installed program in `~/.cogmer/bin` with those arguments and with `COGMER_HOST` set to the host, `claude` when none is named. The hooks call `cogmer-dock hook prompt`, `cogmer-dock hook stop` and `cogmer-dock session-start`. The folder is `scripts/` and not `bin/` because claude.ai rejects a plugin with a top-level `bin/` folder, and cloud sessions can receive cogmer through claude.ai's sync (Claude Code's plugin reference and claude.ai's organization sync page, read on 2026-10-28 and 2026-10-29). On Windows the dock is one executable, since a hook line names one path. D-066 (the binary is fetched and verified, never shipped in the plugin) rejects a binary in the plugin, and the dock is the one exception, so it holds only the logic of starting the program and, on Windows, installing it. Nothing proves that the committed file was built from its source, and a committed file cannot leave the history without breaking the commits that cite it, so the less logic it holds the less is trusted unchecked and the less often it changes. The dock starts the installed program with an argument list, never a command string and never through `cmd.exe`, so the text a user typed reaches the program as the host shell gave it to the dock. The Windows dock installs the program when none is installed (D-273, on Windows the dock installs the program, detached, by the shell installer's rules), and on macOS and Linux the dock is a shell script (D-275, on macOS and Linux the dock is a shell script and a test requires its execute bit). A plugin file is the same text for every user. An exec-form hook has no shell to expand a home-folder variable, and Claude Code's reference lists only the plugin's paths, the project directory and plugin options as expanded. So no file can name a program whose path holds the user's name, and the dock is reached by a path the host fills in. The checksum the installer verifies (D-066, the binary is fetched and verified, never shipped in the plugin) authorizes the program the dock runs.

**Rejected.**
- *The dock in `bin/`, called by bare name.* claude.ai rejects a plugin that has a top-level `bin/` folder, and a bare name in an exec-form hook did not resolve to a plugin's `bin/` folder, since that folder is not on the PATH of an exec-form hook. `1edc1a1`.
- *A `.cmd` dock.* Claude Code's exec form takes an executable and refuses a `.cmd` shim, and `cmd.exe` parses the arguments a second time. Called from PowerShell 5.1, a `.cmd` launcher expanded `%USERNAME%` in an argument and split another at embedded quotes, so the text a user typed arrived changed. Eight argument strings started no second command. `883a8ff`.
- *Adding the program's folder to the user's PATH.* It is a lasting change outside cogmer's own folder, and a host that started before the change never sees it, so the first session after an install fails.
- *The program in `${CLAUDE_PLUGIN_DATA}`.* That folder belongs to one host's plugin, and one program serves every host (D-215, the installer and the daemon replace a program only with a newer version).

**Limits.** The dock is an executable committed to the plugin. D-066 governs the program itself, which is fetched and not shipped. A stand-in program in a plugin's `bin/` folder ran, called by bare name under a scoped rule with a space in the plugin's path (`8c07d61`), and from an exec-form hook by its extensionless plugin-root path (`1edc1a1`). With a script and an `.exe` of the dock's name both in `bin/`, an exec-form hook on Windows ran the `.exe` (`5baeaea`). No dock was run, none from a `scripts/` folder, and these runs used `--plugin-dir`. Windows on ARM64 runs the one executable under emulation, as an amd64 cogmer daemon did on Windows 11 ARM64 (`0f2d509`), and the cost of starting it for every hook call was not measured. That Go starts an executable with `CreateProcess` and no `cmd.exe` is read from Go's documentation and was not run. Cowork's hooks call the bridge (D-205, Claude Cowork is a supported host through a bridge on the user's machine), so Cowork does not use the dock.

**Revisit when** a host gives a hook line the user's home folder, or claude.ai accepts a plugin with a top-level `bin/` folder.

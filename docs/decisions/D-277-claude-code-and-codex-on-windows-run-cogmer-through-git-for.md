# D-277 — Claude Code and Codex on Windows run cogmer through Git for Windows

**Date:** 2026-10-30 · **Status:** active · **Areas:** hosts, release

**Decision.** On Windows the plugin's hooks and command files run through `bash`, which Git for Windows provides, and the README tells a Windows user to install Git for Windows first. A user of Claude Code or Codex without it gets no collaboration. Claude Code finds Git Bash itself, and Codex runs hooks through `cmd.exe`, so for Codex Git's `bin` folder, which holds `bash.exe`, has to be on the PATH. Users of a coding assistant are expected to have Git, and Claude Code's setup page recommends Git for Windows (read on 2026-10-29). Claude Cowork does not run through `bash`, since its hooks call the bridge (D-205, Claude Cowork is a supported host through a bridge on the user's machine), so this decision does not cover it.

**Rejected.**
- *A dock: a Windows executable committed to the plugin that the hooks start without a shell, with a Go installer and a session-start subcommand of the program.* Without Git a session could run its hooks and still not create or join a room, since both are slash commands that bind a session to a room, and a command file runs a shell line that needs `bash`. A command file cannot call the dock by bare name, because that needs a top-level `bin/` folder and claude.ai rejects a plugin that has one (Claude Code's plugin reference and claude.ai's organization sync page, read on 2026-10-28 and 2026-10-29). A full path ran under a scoped PowerShell rule only where it held no space. `0f2d509`, `8c07d61`. The dock also adds a committed executable that nothing proves was built from its source, and a change to the hook lines of every macOS and Linux user, which would then depend on an execute bit that a script run directly needs. `5baeaea`.
- *A shell-form hook line that falls back to a `.cmd` launcher and a PowerShell script.* It ran with and without Git, with a space in the plugin's path (`883a8ff`), but it needs the installer written a second time in PowerShell, and the commands run through `bash`.
- *Installing Git for Windows for the user.* Without Git no hook runs, so nothing in the plugin could install it, and a plugin that installs another program changes the machine beyond cogmer's own folder.

**Limits.** With Git for Windows, Claude Code ran the real plugin's installer and session-start hook (`0f2d509`). With only Git's `cmd` folder on the PATH, the choice its installer recommends (issue 22700 in the Claude Code repository, read on 2026-10-29), Claude Code ran a `bash` hook through Git Bash and Codex failed to run it, and with Git's `bin` folder on the PATH as well Codex ran it (`ada12a8`). Without Git, Claude Code showed no message under `claude -p`, and Codex printed a failure line for the hook (`f62a961`). A portable copy of Git was used, the installer's own PATH choices were not run, and the `bin` folder alone on the PATH was not tried.

**Revisit when** Windows users of Claude Code or Codex without Git are met in numbers, or Claude Code or Codex runs a plugin's hooks without a shell by default.

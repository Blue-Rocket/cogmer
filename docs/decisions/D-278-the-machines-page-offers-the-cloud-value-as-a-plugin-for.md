# D-278 — The machines page offers the cloud value as a plugin for the user to upload once

**Date:** 2026-11-02 · **Status:** not built · **Areas:** identity, view

**Decision.** The machines page offers a zip of a plugin that holds the cloud value as the file `cloud.value` with mode 600, named from a short form of the user's identifier, for the user to upload once as their own plugin and to share and publish nowhere, so that a session started in a browser or on a phone takes its value while none of the user's machines is awake (D-246, a cloud environment is added from the machines page, which shows the one value to paste into it). A plugin uploaded this way reached Cowork sessions started from a browser and from a phone (`7a362f6`) and a Claude Code cloud session (`fb79c55`), and a file in the form of a cloud value arrived with its length, prefix, mode and digest prefix unchanged (`4bd9f95`). The page tells the user, before it offers the plugin, that Anthropic stores the file and that the file holds the relay addresses of the user's machines, which hold no secret (D-104, the overlay address holds no secret and is the same at every start). It tells the user that the organization's administrators can see that the plugin exists (`e282ceb`), and that the user can open the plugin's files in the browser, `cloud.value` among them, in every version an upload over the same name keeps (`e71d3df`, `0f35f77`). It tells the user that each cloud session of the user's account that syncs the account's plugins receives the value, since a plugin shipped disabled is still synced with its file (`7052402`, `9477067`), and that a value left in any copy of the plugin is used until its cloud key is removed (D-279, a cloud session's daemon reads its cloud value from the plugin files it finds, as well as from the variable). It gives the order of a rotation: remove the old cloud key (D-250, a removal of a cloud key names a cutoff for each of its session keys in each room), remove the plugin, upload the new one. Storing the value at a service the user does not run centralizes a credential, and the benefit is the user's, whose sessions join a room from any client while no machine is awake.

**Rejected.**
- *Approving each session from one of the user's machines.* It needs one of the user's machines awake for every session, which a phone session started away from the machines cannot have, and the string the sandbox shows passes through the model.
- *The variable alone.* It leaves a session started in Cowork with no way to receive the value.
- *`defaultEnabled` set to false to limit where the value arrives.* A plugin shipped disabled is still synced with its file, and only its hooks stop (`7052402`, `8474ee4`, `9477067`).

**Limits.** A sandbox reaches the relay only where its network level allows (D-217, a cloud session's daemon carries its relay connection as a WebSocket). An organization owner who turns off user-created skills stops the upload while an installed plugin runs and can be removed (`875e37b`, `e71d3df`), so the user can then revoke and remove but cannot deliver a new value. The model's shell in the sandbox can read the file, as it can read a variable, and a model that looked through the plugin printed its contents unasked (`cac2d7c`, `9477067`), so the value can reach a transcript. The value carries no limit to certain rooms, so a leak gives what the cloud key gives (D-216, a cloud session signs with a key of its own that the user's shared key vouches for).

**Revisit when** a cloud environment can receive a secret without a person pasting it or uploading it.

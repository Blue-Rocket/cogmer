# Claude Code behaviors this project relies on

Generated by `claude-team behaviors --markdown`. Do not edit by hand.

None of these are contractual. Each was established empirically and can change
without notice on a Claude Code upgrade; several fail silently. `claude-team doctor`
re-verifies them against the installed version.

## Tier: offline

### B11 — A hook whose daemon is unreachable exits 0 with empty stdout

**Relied on for:** The guarantee that Claude Code keeps working when collaboration is down. A non-zero exit or stray stdout here would corrupt every prompt.

## Tier: session

### B01 — UserPromptSubmit carries prompt, session_id, transcript_path, prompt_id

**Relied on for:** Prompt capture and session keying. Without session_id the delivery watermark cannot be keyed, and every session would re-inject the whole room.

### B02 — UserPromptSubmit stdout is injected into the pending turn

**Relied on for:** The entire cross-session context feature. If this stops working, teammates become invisible to each other's Claude and only the human-readable room still functions.

### B03 — Stop fires and carries last_assistant_message

**Relied on for:** Half of turn reassembly. Without it the final text block of every turn is lost, because it is not yet on disk when Stop fires.

### B04 — last_assistant_message contains ONLY the turn's final text block

**Relied on for:** mergeTail's append semantics. If Claude Code widens this to the whole turn, naive appending duplicates every pre-tool text block. mergeTail already tolerates the change; this check exists to report it rather than let it pass unnoticed.

### B05 — The transcript at Stop time is missing the final text block

**Relied on for:** Why reassembly unions two sources instead of just reading the transcript. If this race disappears, the union becomes redundant but stays correct.

### B06 — Human prompts carry promptSource; tool-result records do not

**Relied on for:** Turn segmentation and prompt filtering. If tool-result records gained a promptSource, reassembly would anchor on the wrong record and publish a fragment of the turn.

### B07 — Assistant content blocks use type text / tool_use / thinking

**Relied on for:** Response extraction and the rule that thinking is never published to the room.

### B08 — isSidechain marks subagent traffic

**Relied on for:** Keeping subagent output -- including the compaction summarizer's -- out of the shared room.

### B09 — Assistant records carry no promptId

**Relied on for:** Why segmentation is positional. If assistant records gained a promptId, segmentation could become exact -- an improvement worth taking, not a break.

### B10 — PostToolUse carries tool_name and tool_response

**Relied on for:** Tool-activity metadata on stored events.

### B12 — Reassembly reconstructs the complete turn

**Relied on for:** End-to-end proof that B03/B04/B05 still compose. This is the check that matters if the individual ones drift.

### B20 — Injected hook output is recorded as a hook_success attachment

**Relied on for:** Delivery confirmation (D-014). The daemon marks teammate events delivered only once it observes the injected block in the transcript. If this record disappears or changes shape, delivery falls back to trusting that the turn carried it -- degraded, not broken, but the guarantee weakens silently.

## Tier: compaction

### B13 — PreCompact fires and reports its trigger

**Relied on for:** Detecting compaction at all. Without it, compaction is only visible by reading the transcript after the fact.

### B14 — session_id and transcript_path survive compaction

**Relied on for:** The delivery watermark is keyed on session ID. A new ID per compaction would silently re-inject the entire room every time.

### B15 — The transcript is appended to across compaction, never rewritten

**Relied on for:** Reassembly anchors on a record written before the boundary. A rewritten transcript could remove the anchor.

### B16 — Compaction writes a compact_boundary marker and a summary record

**Relied on for:** Detecting a compaction from the transcript alone, without having caught the hook.

### B17 — The compaction summary record carries no promptSource

**Relied on for:** Reassembly must not mistake the summary for a human prompt. If it did, every post-compaction turn would anchor on the summary and publish the wrong text.

### B18 — Slash commands do not reach UserPromptSubmit

**Relied on for:** Keeping /compact and other slash commands out of the room. If this changes, every slash command becomes a published conversation event.

### B19 — Injected teammate context survives compaction

**Relied on for:** Why no watermark rewind exists. If this fails, sessions are marked as having incorporated context they can no longer see, and the referent is lost silently. Remediation is documented in docs/phase0a-findings.md §5.

Read in the code of Claude Code 2.1.328 on the droplet, not observed
  A diskless session, one whose launch options say diskless, filters the hooks it runs. From a plugin it keeps
  command and prompt hooks, agent hooks and http hooks, and it keeps mcp_tool hooks only from project settings.
  The function that runs an mcp_tool hook refuses in a diskless session with "MCP tool hook not run: a cloud
  session does not run command, script, HTTP or MCP tool hooks from the shared server it runs on".
  Where CLAUDE_CODE_REMOTE is true, an mcp_tool hook naming remote-devices is refused with "Hooks can't call
  tools of MCP server '…' in a cloud session, because that server acts on your computer or browser and a hook's
  call skips the permission check."
  An agent hook's model gets the session's tools less a few, and when the launch option toolsMayBeOnHost holds,
  only one tool that is not from an MCP server. A message reads "A hook agent evaluating a call served for a cloud
  session may not run a destructive command here".
  "dynamic" is a configuration scope that Claude Code gives a server added while it runs rather than read from a
  settings file, among them a plugin's servers and a connector a host hands in, which one place in the code
  describes as type http, scope dynamic, source dynamic and provenance connector.
  A bundled command, /debug, turns on debug logging while a session runs.
